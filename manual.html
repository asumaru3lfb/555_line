最初に読む

この仕組みは、何がどこで動いているか

4つの管理画面を、目的別に行き来しながら運用します。それぞれ「何をするための画面か」だけ覚えておけば、迷ったときにどこを見ればいいか分かります。

① LINE Official Account Manager

お客さま向けの管理画面。友だち数の確認、リッチメニューの見た目確認、配信メッセージの作成、「チャット」機能のON/OFF切り替えをここで行う。
manager.line.biz

② LINE Developers コンソール

エンジニア向けの管理画面。Webhook URLの設定確認、チャネルシークレット／アクセストークンの再発行をここで行う。
developers.line.biz

③ Cloudflareダッシュボード

Bot本体のプログラム（Workers）、会員データ（D1）、ファイル置き場（R2）を管理する画面。エラーログの確認・データの中身の確認もここで行う。
dash.cloudflare.com

④ ターミナル（wrangler）

本番環境へコードやデータベースの変更を反映（デプロイ）するための操作。パソコンにインストールした「wrangler」というコマンドツールを使う。

ふだんの運用で使う画面（多い順）

  1. ①LINE Official Account Manager — 友だち数の確認、配信、リッチメニューの見た目チェック。最も頻繁に開く画面。
  2. ③Cloudflareダッシュボード — 「メッセージが届かない」等のトラブル時にログを見る。データを確認したいときにD1を開く。
  3. ②LINE Developers — 通常はほぼ開かない。シークレットの再発行が必要になったときだけ。
  4. ④ターミナル — コードやリッチメニュー画像を更新するときだけ。日常の運用では基本的に使わない。
合言葉：「お客さまに見える部分（友だち追加・メッセージ・メニュー）」はLINE管理画面、「裏側の仕組み（プログラム・データ・エラー）」はCloudflare、と覚えると迷いません。
manager.line.biz

LINE Official Account Manager の使い方

お客さま向けの管理画面。ここではアカウントの見た目・配信・友だちの状況を確認します。

ログイン方法

ブラウザで manager.line.biz を開く
アドレスバーに https://manager.line.biz と入力してアクセスします。
LINEアカウントでログイン
「大洲カンパニー」の管理者権限を持つLINEアカウント（またはメールアドレス）でログインします。権限が分からない場合は三好へ確認してください。
アカウントを選択
複数アカウントを管理している場合、ログイン後の一覧から「大洲カンパニー」を選びます。

「チャット」機能は必ずOFFにしておく

重要：「チャット」機能がONだと、お客さまからのメッセージがBot（Cloudflare Workers）に届かず、この管理画面上の「チャット」に横取りされてしまい、自動応答が一切動かなくなります。
設定画面を開く
画面左メニュー「ホーム」→右上の歯車アイコン「設定」 を開きます。
応答設定を確認
「応答設定」 のページで、「チャット」がオフになっていることを確認します。オンになっていたらオフに切り替えてください。「Webhook」は逆にオンである必要があります。

リッチメニューの見た目を確認する

リッチメニュー管理画面を開く
画面左メニュー「トーク画面管理」→「リッチメニュー」
現在使われているメニューを確認
一覧に表示されている画像とタイトルを確認します。ただし本アカウントのリッチメニューはターミナル（wrangler）からLINE APIを直接呼び出して登録しているため、ここから新規作成・編集は行いません（詳しくは「ターミナル操作」タブ）。

友だち数・統計を見る

分析画面を開く
画面左メニュー「分析」
友だち数の推移・ブロック率を確認
「友だちの推移」グラフで日次の増減、「概要」タブでブロック率を確認できます。

メッセージを配信する（一斉配信）

配信作成画面を開く
画面左メニュー「チャット・配信」→「メッセージ配信」→「作成」
配信内容を作成
テキスト・画像・カードなどを選び、内容を入力します。
配信対象を絞り込む（必要な場合）
「配信先」で属性やタグによる絞り込みが可能ですが、本アカウントの回答データ（推し・お住まい等）はLINE側のタグ機能ではなくCloudflare D1に保存されているため、D1側のデータで絞り込んだ上で、対象者にだけ個別配信したい場合はBot側の実装が別途必要です（現状未実装。積み残しタスク参照）。
配信予約または即時配信
内容を確認して配信します。配信後の取り消しはできないため、必ずプレビューで見え方を確認してください。
developers.line.biz

LINE Developers コンソールの使い方

ふだんはほとんど開きませんが、Webhookが届かない・認証エラーが出るときに必ず確認する画面です。

ログインとチャネルの開き方

developers.line.biz を開いてログイン
manager.line.bizと同じLINEアカウントでログインできます。
プロバイダーを選択
一覧から本プロジェクトのプロバイダーを選びます。
Messaging APIチャネルを選択
チャネル一覧から「大洲カンパニー」（チャネルID：2011331444）を選びます。

Webhook URLを確認する

「Messaging API設定」タブを開く
チャネル詳細画面の上部タブから Messaging API設定 を選びます。
Webhook URLを確認
「Webhook URL」の欄に、Cloudflare Workersのアドレス（https://〜.workers.dev または独自ドメイン）が正しく入っているか確認します。「検証」ボタンを押すと接続確認ができます（成功と出ればWorker側は正常に応答している状態）。
「Webhookの利用」がオンになっているか確認
同じ画面内のスイッチがオンになっている必要があります。

チャネルシークレット／アクセストークンを再発行する

注意：再発行すると古い値は即座に無効になります。再発行後は必ずCloudflare側のシークレットも更新（下記「ターミナル操作」参照）しないと、Botが一切応答しなくなります。
チャネルシークレットの場所
「チャネル基本設定」タブ→「チャネルシークレット」 欄。「発行」または「再発行」ボタンで更新できます。
チャネルアクセストークンの場所
「Messaging API設定」タブ→「チャネルアクセストークン（長期）」 欄。「発行」で新しいトークンが表示されます（表示は一度きりなので、その場でコピーしてターミナルに貼り付けます）。
dash.cloudflare.com

Cloudflareダッシュボードの使い方

Bot本体のプログラム（Workers）・会員データ（D1）・ファイル置き場（R2）を確認する画面です。

ログイン方法

dash.cloudflare.com を開く
Cloudflareアカウントのメールアドレスとパスワードでログインします。
正しいアカウントを選択
画面左上のアカウント名が、本プロジェクトを運用しているアカウント（一般社団法人キタ・マネジメント名義）になっているか確認します。

Workers（プログラム本体）を見る

Workers & Pages を開く
画面左メニュー「Compute（Workers）」→「Workers & Pages」
対象のWorkerを選択
一覧から ozu555-line-worker を選びます。
ログを見る
「Logs」タブ→「Begin log stream」 を押すと、リアルタイムのアクセスログ・エラーが流れ始めます（この後に実際にLINEでメッセージを送ると、その処理内容がここに表示されます）。
設定値（環境変数）を見る
「Settings」タブ→「Variables and Secrets」 で、GREETING_RALLYなどの設定値を確認できます（シークレット系の値そのものは表示されず、更新のみ可能）。

D1（会員データベース）を見る

D1の一覧を開く
画面左メニュー「Storage & Databases」→「D1 SQL Database」
対象のデータベースを選択
一覧から本番用データベース（database_id: a9fff12a-791b-4c4a-b2b5-761992441af5）を選びます。
テーブルの中身を見る
「Tables」タブ でテーブル一覧（members / member_pii / member_attributes / member_referrals / member_tags / member_events）が見られ、クリックすると中身の行が一覧表示されます。
SQLを直接実行して調べる
「Console」タブ にSQL文を入力して「Execute」を押すと、その場で結果が表示されます。具体的な文例は「データの見方」タブ参照。
注意：ConsoleからDELETEやUPDATEを直接実行すると、Bot側のコードを経由せずデータが変更されます。原則として「見るだけ」に使い、変更が必要な場合は事前に丸岡さんに相談してください。

R2（ファイル置き場）を見る

R2の一覧を開く
画面左メニュー「Storage & Databases」→「R2 Object Storage」
バケットを開いて中身を見る
対象のバケットを選ぶと、フォルダ・ファイルの一覧が見られます。webhook_fallback/ 以下は、Webhook処理に失敗した際の取りこぼしデータの一時保管場所です。
wrangler CLI

ターミナル操作（コードやデータの更新）

本番環境にコード・データベース構造・秘密情報を反映するときだけ使います。日常の運用では基本的に触りません。

事前準備（初回のみ）

Node.jsをインストール
公式サイト（nodejs.org）からLTS版をインストールします。
プロジェクトフォルダを開く
ターミナル（PowerShellまたはコマンドプロンプト）で ozu555-line-worker フォルダに移動します。
依存パッケージをインストール
# プロジェクトフォルダ内で実行 npm install
Cloudflareにログイン
npx wrangler login
ブラウザが自動で開くので、Cloudflareアカウントでログイン・許可します。

コードを本番へ反映する（デプロイ）

npx wrangler deploy

実行するとCloudflare上のWorkerが即座に新しいコードに置き換わります。数秒〜十数秒で反映されます。

データベースの構造を変更する（マイグレーション適用）

後戻りしにくい操作：本番データベースへの適用は取り消せません。--remote を付けると本番に、付けないとローカルの確認用に適用されます。
# まずローカルで確認してから npx wrangler d1 migrations apply ozu555-line-db # 問題なければ本番へ npx wrangler d1 migrations apply ozu555-line-db --remote

秘密情報（シークレット）を設定する

npx wrangler secret put LINE_CHANNEL_SECRET # Enterを押すと値の入力を求められるので、貼り付けてEnter npx wrangler secret put LINE_CHANNEL_ACCESS_TOKEN npx wrangler secret put ADMIN_TOKEN

値は画面に表示されず、入力してEnterを押すだけで登録されます。LINE Developersでシークレットやトークンを再発行した直後は、必ずこのコマンドで更新してください。

リッチメニューを更新する

画像を作り直す
scratchpad/make_richmenu3.py（Python）を編集・実行し、新しい画像を生成します。
管理用APIを呼び出して登録する
# PowerShellの場合 Invoke-RestMethod -Method Post ` -Uri "https://ozu555-line-worker.〜.workers.dev/admin/setup_richmenu" ` -Headers @{ "Authorization" = "Bearer （ADMIN_TOKENの値）" }
このAPIが「新しい画像で登録→デフォルトに設定→古いメニューを削除」までを自動で行います。
LINEアプリで確認
トーク画面を一度閉じて開き直すと、新しいメニューに切り替わります（反映までに数分かかる場合があります）。

リアルタイムでログを見る

npx wrangler tail --format json

実行した状態でLINE上から操作すると、その処理内容がターミナルに逐次表示されます。response.statusが401ならシークレットの不一致、500ならコード側のエラーです。

D1 Console

データの見方（SQLの実行例）

Cloudflareダッシュボードの D1 SQL Database→対象DB→Console タブに、以下のSQL文をそのまま貼り付けて「Execute」を押してください。

友だち数を確認する

SELECT COUNT(*) AS 友だち数 FROM members WHERE unfollowed_at IS NULL;

直近で友だち追加した人を新しい順に見る

SELECT line_user_id, followed_at, stage FROM members ORDER BY followed_at DESC LIMIT 20;

ある人の回答内容をまとめて見る（1人分）

line_user_id の値は、上記のmembers一覧やmember_eventsのidempotency_keyなどから調べられます。

-- 属性（推し・関係・お住まい） SELECT * FROM member_attributes WHERE line_user_id = '（対象のID）'; -- 関わり方の希望タグ SELECT * FROM member_tags WHERE line_user_id = '（対象のID）'; -- 紹介元・紹介者名 SELECT * FROM member_referrals WHERE line_user_id = '（対象のID）';

「推し」の回答分布を見る（簡易集計）

SELECT oshi, COUNT(*) AS 件数 FROM member_attributes GROUP BY oshi ORDER BY 件数 DESC;

直近のイベントログを見る（動作確認・トラブル調査用）

SELECT line_user_id, event_type, created_at FROM member_events ORDER BY created_at DESC LIMIT 50;
テーブル名ここに何が入っているか
members会員の土台。友だち追加日・退会日・現在の状態
member_pii表示名・メールアドレスのみ（個人特定情報）
member_attributes推し・大洲との関係・お住まい（統計的な属性）
member_referrals紹介元の種別・紹介者のお名前（第三者情報）
member_tags関わり方の希望など、複数選択できるタグ
member_eventsいつ・何をしたかの記録ログ

各テーブルの設計思想の詳細は「設計ドキュメント一式」タブの「データベース設計書」を参照してください。

症状別チェックリスト

困ったときは、まずここを確認する

症状：メッセージを送っても既読にならない・返信が来ない

LINE Official Account Managerの「チャット」設定を確認
ホーム→設定→応答設定 で「チャット」がオフになっているか確認（オンだと横取りされます）。
LINE Developersで接続確認
Messaging API設定→Webhook URL→検証 を押し、成功するか確認。
wrangler tailでログを見る
ターミナルで npx wrangler tail --format json を実行し、実際にLINEでメッセージを送ってみる。response.statusが401ならシークレット不一致 → LINE Developersで値を確認し、ターミナルから wrangler secret put で再設定。

症状：リッチメニューが表示されない・古いまま

トーク画面を閉じて開き直す
LINEアプリ側のキャッシュが原因のことが多いです。
数分待つ
LINEプラットフォーム側の反映に時間がかかる場合があります。
それでも直らない場合は再登録
「ターミナル操作」タブの「リッチメニューを更新する」手順で、/admin/setup_richmenuを再実行します。

症状：Cloudflareへのデプロイ・マイグレーションが失敗する

エラーメッセージを確認
"not authorized: SQLITE_AUTH" の場合、SQL文の中に PRAGMA や CREATE TEMP TABLE が含まれていないか確認してください（D1では使用不可）。
ログイン状態を確認
npx wrangler login を再実行し、正しいCloudflareアカウントでログインしているか確認します。

症状：友だち追加してもDBに何も記録されない

D1 Consoleで直接確認
SELECT * FROM members ORDER BY followed_at DESC LIMIT 5; を実行し、新しい行が増えているか確認。
増えていなければwrangler tailでエラーを確認
followイベント処理中の例外（SQLエラー等）が表示されていないか確認します。
共通の心構え：まず「LINE側の設定」→「Webhookの接続」→「Cloudflare側のログ」の順に切り分けると、原因の層（LINE側かCloudflare側か）を早く特定できます。
